# Tích hợp Thanh toán PayOS

## Context

Dự án đã có **toàn bộ** luồng nghiệp vụ đơn hàng (consultation→order→staff review→confirm→production), nhưng **không tích hợp bất kỳ cổng thanh toán nào**. Hiện tại chỉ có 2 phương thức thủ công:

- **COD**: nhận hàng mới thanh toán → không cần automation
- **Bank transfer**: hiển thị thông tin hardcoded (Vietcombank placeholder) + upload ảnh màn hình → nhân viên kiểm tra thủ công

Customer sau khi tạo đơn trên `/dashboard/checkout` hoặc `/order/from-consultation/*` chỉ thấy trang "Thank you" rồi rời đi. **Không có nút "Thanh toán", không có redirect sang cổng thanh toán, webhook nào không tồn tại.**

Mục tiêu: tích hợp **PayOS** làm cổng thanh toán online chính, giữ nguyên Cod/bank transfer làm fallback. Khi customer chọn PayOS + thanh toán thành công (webhook) → tự động cập nhật `payment_status` và chuyển đổi trạng thái đơn phù hợp.

## Scope

### Trong phạm vi (v1)
1. Thêm trường `payos_payment_id` trên bảng `orders`
2. Backend: 3 route mới cho PayOS SDK
3. Frontend: gắn nút "Thanh toán ngay" vào order detail + checkout success
4. Webhook handler cho PayOS callback
5. Nhân viên có thể xem trạng thái thanh toán trong staff dashboard

### Ngoài phạm vi (tránh scope creep)
- Hoàn tiền / refund
- Chia nhỏ thanh toán (partial payment) — B2B thường trả trọn gói
- Cổng thanh toán khác (MoMo, ZaloPay…) → trừu tượng hóa sau nếu cần

## Bước thực hiện chi tiết

### Bước 1 — Migration & Schema

Thêm cột mới trên `orders`:
- **`payos_payment_id TEXT NULL`** — lưu transaction ID từ PayOS (nếu có)

File: `supabase/migrations/YYYYMMDDHHMMSS_add_payos_payment_id.sql`

```sql
ALTER TABLE orders ADD COLUMN payos_payment_id TEXT;
CREATE INDEX IF NOT EXISTS idx_orders_payos_payment_id ON orders(payos_payment_id) WHERE payos_payment_id IS NOT NULL;
```

Update `src/types/database.ts` để reflect schema mới.

### Bước 2 — Service layer PayOS

Tách PayOS logic khỏi route handlers.

File: `src/lib/payos/client.ts`
- Hàm `createPaymentLink(orderId, orderCode, totalAmount, description, returnUrl)` → trả về `{ paymentUrl, payosPaymentId }`
- Hàm `verifyWebhook(payload, checksum)` → validate chữ ký PayOS
- Đọc keys từ env vars: `PAYOS_CLIENT_ID`, `PAYOS_API_KEY`, `PAYOS_CHECKSUM_KEY`

File: `src/lib/payos/webhook.ts`
- Hàm `handlePayOSWebhook(body)` — verify, tìm order, update payment_status, trigger status transition

### Bước 3 — API Routes Backend

#### 3a. `POST /api/orders/[id]/payos/create`
- Auth: customer only
- Validate order đang ở trạng thái được phép thanh toán (`pending` | `staff_review` | `confirmed`)
- Gọi `createPaymentLink()` với `total_amount` + `description` = `${order_code}`
- Lưu `payos_payment_id` vào order row
- Trả về `{ paymentUrl }`

#### 3b. `POST /api/payos/webhook` (public)
- Không auth (PayOS gọi từ outside)
- Verify checksum theo docs PayOS (HMAC-SHA256)
- Tìm order theo `payos_payment_id` hoặc `orderCode` từ webhook payload
- So sánh `amount` từ webhook vs `total_amount` của order
- Nếu match:
  - Set `payment_status = 'paid'`
  - Set `payment_method = 'payos'` (cần thêm vào CHECK constraint của DB)
  - Trigger status transition: nếu `status == 'confirmed'` → chuyển sang `'production'`; nếu `status != 'confirmed'` → giữ nguyên
- Ghi log vào `order_status_history` (note: "Thanh toán thành công qua PayOS")
- Trả về `{ status: "Success" }` — HTTP 200

#### 3c. `GET /api/orders/[id]/payos/status`
- Auth: customer hoặc staff
- Trả về payment metadata + current status

#### 3d. Update DB constraint
Migration thêm `'payos'` vào CHECK constraint của `payment_method`:
```sql
ALTER TABLE orders DROP CONSTRAINT orders_payment_method_check;
ALTER TABLE orders ADD CONSTRAINT orders_payment_method_check 
  CHECK (payment_method IN ('cod', 'bank_transfer', 'payos'));
```

## Rủi ro & Mitigation

| Risk | Mitigation |
|------|-----------|
| Localhost không nhận webhook | Dùng ngrok/Cloudflare tunnel expose port 3000 |
| Webhook duplicate call | Kiểm tra `payment_status` trước khi update (idempotent) |
| Amount bị lệch do giá sản phẩm thay đổi | Store price snapshot tại thời điểm tạo đơn; webhook so với snapshot |
| Customer bỏ dở PayOS → đơn stuck | Không block status, nhân viên vẫn xử lý thủ công |
| `payment_method` CHECK constraint fail | Migration drop+add trong cùng file migration |
